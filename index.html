01 db/db_connection.php DB

Four values are always required. The fifth is optional.

CLASS DBConnection

    private host     = 'localhost'   1. where MySQL runs
    private username = 'root'        2. DB user         
    private password = ''            3. blank on XAMPP  
    private dbname   = 'wtm'         4. database name   
    5. port = 3306 - optional, defaults to this

    FUNCTION connect()
        conn = new mysqli(host, username, password, dbname)
        IF conn -> connect_error THEN
            die("Connection failed: " . conn->connect_error)
        END IF
        RETURN conn
    END FUNCTION

END CLASS

Name all four if you are asked: host, username, password, database name. The port is the optional fifth and defaults to 3306.

The die() matters. Without it a wrong password produces a blank white page and no clue why.

02 model/User.php → addUser() MODEL

The add-user query. Seven placeholders, seven letters.

FUNCTION addUser(username, email, password,
                 gender, department, interests, newsletter)

    sql = "INSERT INTO users
           (username, email, password, gender,
            department, interests, newsletter)
           VALUES (?, ?, ?, ?, ?, ?, ?)"

    connection = establishConnection()
    stmt = connection -> prepare(sql)

    one letter per ? , in the SAME order
    s = string   i = integer           
    d = decimal  b = blob              
    stmt -> bind_param('ssssssi', username, email, password,
                          gender, department, interests, newsletter)

    IF stmt -> execute() THEN
        RETURN connection -> insert_id    the new row's id
    ELSE
        RETURN false
    END IF
END FUNCTION

'ssssssi' — count them: six strings, then one integer for newsletter. The letters must match the question marks one for one, in order. Get the count wrong and MySQL says Number of variables doesn't match parameters.

Why this stops SQL injection: the query text goes to MySQL first, with the question marks still in it. The values follow separately, afterwards. MySQL already knows what the query looks like, so a value can never change its shape — typing ' OR '1'='1 just stores that as a username.

Radio — the shared name is what groups them.
Select — name on the <select>, and the chosen option's value is sent.

05 Session and cookies CONTROLLER

Set both at the same moment, then watch logout treat them differently.

---------- LOGIN ----------
row = model -> loginCheck(username, password)
IF row is not null THEN
    SESSION - on the server
    $_SESSION['username']   = row['username']
    $_SESSION['department'] = row['department']

    COOKIE - in the browser, 7 days
    setcookie('last_user', row['username'],
              time() + (60 * 60 * 24 * 7), '/')
END IF


---------- LOGOUT ----------
session_start()
session_unset()      empties $_SESSION      
session_destroy()    destroys it on the server
the last_user cookie is deliberately NOT touched


---------- THEME TOGGLE ----------
IF isset($_COOKIE['theme']) AND == 'dark' THEN
    setcookie('theme', 'light', one_week, '/')
ELSE
    setcookie('theme', 'dark',  one_week, '/')
END IF

reading it back, on every page
theme = isset($_COOKIE['theme']) ? $_COOKIE['theme'] : 'light'


---------- DELETING A COOKIE ----------
set it again with an expiry in the PAST
setcookie('last_user', '', time() - 3600, '/')

After logout the session is gone but the cookie remains, so the login page can still say Welcome back, nusrat. That single behaviour is the clearest possible demonstration of the difference, and it is why the two are set side by side here.

A cookie expiry is an absolute moment in time, not a duration — always time() + seconds.

Never leave a delete line in the toggle handler. A trailing setcookie('theme', '', time()-3600) runs on every request and wipes the cookie you just set, so the theme can never change. Keep deletion in its own file.
06 Session vs Cookie CONCEPT

The comparison, and the one sentence that explains it all.

                  SESSION              COOKIE

Stored where      on the SERVER        in the BROWSER
Created with      session_start()      setcookie()
Read with         $_SESSION            $_COOKIE
Lifetime          until browser        until the expiry
                  closes / destroy     date you set
Deleted with      session_destroy()    an expiry in the PAST
Size limit        large (server)       about 4 KB
User can edit?    No - they only       Yes - it sits on
                  hold the id          their machine
Good for          login state,         theme, "remember me",
                  anything private     preferences

Why login is a session and the theme is a cookie: a cookie lives on the user's own computer, so they can edit it. Nobody may edit their way into being logged in, so login state belongs in a session. A theme is harmless and should still be there tomorrow, so it belongs in a cookie.

The browser only ever holds the session id. The actual values sit on the server, out of reach.

07 view/superglobals.php VIEW

A superglobal is an array PHP builds for you, available everywhere.

$_GET      values from the URL
           ?target=x&demo=hello  ->  $_GET['demo']

$_POST     values from a form with method="post"

$_REQUEST  $_GET and $_POST together

$_SESSION  kept on the SERVER, dies at logout
           needs session_start() first

$_COOKIE   kept in the BROWSER, survives logout

$_FILES    uploaded files. STAYS EMPTY unless the form
           has enctype="multipart/form-data"

$_SERVER   information about the request and server
           REQUEST_METHOD   'GET' or 'POST'
           PHP_SELF         path of the running script
           SCRIPT_NAME      same, from the server
           HTTP_HOST        e.g. localhost
           QUERY_STRING     everything after the ?
           HTTP_USER_AGENT  which browser is asking

printing one to inspect it
print_r($_POST);   OR   var_dump($_POST);

Definition to write down: a superglobal is a built-in array that PHP fills in automatically and that is available in every file and inside every function, without declaring global.

$_SERVER['REQUEST_METHOD'] is the one you use most — it is what every controller checks to tell a real form submission from someone simply opening the file in the address bar.

The one condition that leaves $_FILES empty: a form without enctype="multipart/form-data". The browser then sends only the file's name as ordinary text, and no error is shown anywhere.

Question 7 · 30 marks

Watching the Loop Run

Output tracing is not guesswork. Every program is unrolled one pass at a time: what the condition asks, what the answer is, what gets printed, and what every variable holds afterwards.

Arraysfor / foreach / whileif / else ifbreak & continueVERIFIED ON PHP 8.2

How to trace a loop, every time:

1. Write the variables down the side and give each a starting value.
2. Do one pass out loud: test the condition, run the body, update.
3. Write printed text on a separate ‘screen’ line as you go.
4. Repeat until the condition fails — then remember the counter was increased one last time.

PROGRAM 1

Indexed array, for loop, if / else

5 MARKS

The plainest possible loop. Get the habit right here and the other five are the same motion.

The code

$numbers = [12, 7, 20, 5, 18];
$sum = 0;
for ($i = 0; $i < count($numbers); $i++) {
    if ($numbers[$i] % 2 == 0) {
        echo $numbers[$i] . " is even<br>";
        $sum = $sum + $numbers[$i];
    } else {
        echo $numbers[$i] . " is odd<br>";
    }
}
echo "Sum of even numbers: " . $sum;

Unrolled, one pass at a time

start
$numbers = [12, 7, 20, 5, 18]   count is 5
$sum     = 0
$i       = 0
prints nothing $sum = 0 Nothing printed yet.
$i = 0
0 < 5 ?  yes
$numbers[0] is 12  ->  12 % 2 == 0 ?  yes, even
prints 12 is even $sum = 0 + 12 = 12
$i = 1
1 < 5 ?  yes
$numbers[1] is 7   ->  7 % 2 == 0 ?  no, odd
prints 7 is odd $sum stays 12 The else branch does not touch $sum.
$i = 2
2 < 5 ?  yes
$numbers[2] is 20  ->  20 % 2 == 0 ?  yes, even
prints 20 is even $sum = 12 + 20 = 32
$i = 3
3 < 5 ?  yes
$numbers[3] is 5   ->  5 % 2 == 0 ?  no, odd
prints 5 is odd $sum stays 32
$i = 4
4 < 5 ?  yes
$numbers[4] is 18  ->  18 % 2 == 0 ?  yes, even
prints 18 is even $sum = 32 + 18 = 50
$i = 5
$i++ makes $i = 5
5 < 5 ?  NO  ->  the loop stops here
prints nothing $i = 5, $sum = 50 The body did not run a sixth time.
after
echo "Sum of even numbers: " . $sum;
prints Sum of even numbers: 50 $sum = 50

What the browser shows

12 is even 7 is odd 20 is even 5 is odd 18 is even Sum of even numbers: 50

Each <br> ends a line, so five array items give five lines, and the total is printed on a sixth.

The question they always add: how many times did the body run, and what is $i at the end?

The body ran 5 times — once per item. But $i ends up as 5, not 4. The order is always: run the body, then $i++, then test the condition. So the counter always ends one past the last value it actually used.

Sum of the even ones: 12 + 20 + 18 = 50.

PROGRAM 2

Associative array, foreach, if / else if / else

5 MARKS

An if/else-if chain stops at the first true condition. That single fact is the whole answer here.

The code

$marks = array("Rahim" => 78, "Karim" => 92,
               "Ayesha" => 55, "Nusrat" => 43);
foreach ($marks as $name => $mark) {
    if ($mark >= 90)      { $grade = "A+"; }
    else if ($mark >= 70) { $grade = "A";  }
    else if ($mark >= 50) { $grade = "B";  }
    else                  { $grade = "F";  }
    echo $name . " scored " . $mark . " and got " . $grade . "<br>";
}
echo "Total students: " . count($marks);

One pass per key/value pair

start
the array has 4 pairs:
  "Rahim" => 78   "Karim" => 92
  "Ayesha" => 55  "Nusrat" => 43
prints nothing foreach hands over one key and one value at a time.
pair 1
$name = "Rahim", $mark = 78
78 >= 90 ?  no
78 >= 70 ?  YES  ->  stop testing, $grade = "A"
prints Rahim scored 78 and got A $grade = "A"
pair 2
$name = "Karim", $mark = 92
92 >= 90 ?  YES  ->  stop testing, $grade = "A+"
prints Karim scored 92 and got A+ $grade = "A+" 92 is also ≥ 70, but that line is never reached.
pair 3
$name = "Ayesha", $mark = 55
55 >= 90 ?  no
55 >= 70 ?  no
55 >= 50 ?  YES  ->  $grade = "B"
prints Ayesha scored 55 and got B $grade = "B"
pair 4
$name = "Nusrat", $mark = 43
43 >= 90 ?  no
43 >= 70 ?  no
43 >= 50 ?  no
  ->  the else runs, $grade = "F"
prints Nusrat scored 43 and got F $grade = "F"
after
no pairs left  ->  loop ends

prints Total students: 4 count = 4

What the browser shows

Rahim scored 78 and got A Karim scored 92 and got A+ Ayesha scored 55 and got B Nusrat scored 43 and got F Total students: 4

Four pairs give four lines, plus the count on a fifth.

Karim is the trap. 92 satisfies >= 90, >= 70 and >= 50 — but an if / else if chain stops dead at the first one that is true. Write A+, not A.

Why can this not use a for loop?

The keys are "Rahim", "Karim" and so on — not 0, 1, 2, 3. So $marks[0] does not exist and $marks[$i] would find nothing. An associative array has to be walked with foreach; a for loop with count() only works on an indexed array like Program 1's.

PROGRAM 3

Two-dimensional array and continue

5 MARKS

An array of arrays, and the keyword that abandons one pass without leaving the loop.

The code

$students = [
    ["name" => "Rahim",  "cgpa" => 3.50],
    ["name" => "Karim",  "cgpa" => 2.80],
    ["name" => "Ayesha", "cgpa" => 3.90],
    ["name" => "Tanvir", "cgpa" => 2.95]
];
$count = 0;
for ($i = 0; $i < count($students); $i++) {
    if ($students[$i]["cgpa"] < 3.0) {
        continue;
    }
    $count++;
    echo $count . ". " . $students[$i]["name"]
       . " (" . $students[$i]["cgpa"] . ")<br>";
}
echo "Eligible: " . $count . " out of " . count($students);

Unrolled, one pass at a time

start
$students has 4 rows
$count = 0
$i = 0
prints nothing $count = 0 Each row is itself an array with two keys.
$i = 0
$students[0]["cgpa"] is 3.50

$count++  ->  $count is now 1
prints 1. Rahim (3.5) $count = 1 Printed as 3.5, not 3.50.
$i = 1
$students[1]["cgpa"] is 2.80
2.80 < 3.0 ?  YES  ->  continue

jumps straight to $i++ - the rest
of the body is skipped entirely
prints nothing $count stays 1 $count++ never runs for Karim.
$i = 2
$students[2]["cgpa"] is 3.90
3.90 < 3.0 ?  no
$count++  ->  $count is now 2
prints 2. Ayesha (3.9) $count = 2 Numbered 2, not 3.
$i = 3
$students[3]["cgpa"] is 2.95
2.95 < 3.0 ?  YES  ->  continue
prints nothing $count stays 2
$i = 4
4 < 4 ?  NO  ->  the loop stops

Only two of the four students are printed, and they are numbered 1 and 2 — not 1 and 3.

Two traps in one program. First: the code says 3.50 but the output is 3.5 — PHP stores it as the number 3.5, and a number carries no trailing zero. Second: $count++ sits after the continue, so skipped students never consume a number.

continue vs break

continue abandons the current pass and jumps to the next one — the loop carries on.
break leaves the whole loop immediately — nothing after it runs.

If continue here were break, the output would stop after Rahim and read Eligible: 1 out of 4.

PROGRAM 4

while (true), break and array_push

5 MARKS

A loop with no condition of its own. The only way out is the break inside it.

The code

$cart = [];

while (true) {

1 % 2 != 0 ?  YES, odd  ->  push 1 * 10

prints nothing $cart = [10], $i -> 2 array_push prints nothing.
$i = 2
2 > 5 ?  no
2 % 2 != 0 ?  no, even  ->  nothing pushed
$i++
prints nothing $cart = [10], $i -> 3
$i = 3
3 > 5 ?  no
3 % 2 != 0 ?  YES  ->  push 30
$i++
prints nothing $cart = [10, 30], $i -> 4
$i = 4
4 > 5 ?  no
4 % 2 != 0 ?  no
$i++
prints nothing $cart = [10, 30], $i -> 5
$i = 5
5 > 5 ?  no
5 % 2 != 0 ?  YES  ->  push 50
$i++
prints nothing $cart = [10, 30, 50], $i -> 6
$i = 6
6 > 5 ?  YES  ->  break

leaves the loop at once - $i is never 
increased again, so it stays 6
prints nothing $i = 6
after

print_r uses a fixed layout: the word Array, a bracket alone on the next line, then four spaces before each [key] => value, then a closing bracket. Note the blank line after ) — explained below.

Three traps here. (1) The last value of $i is 6, not 5 — it was raised to 6 at the end of the previous pass, and the break then fired on the way in. (2) print_r already ends with a newline, so the <br> in echo "<br>Items: " adds a second one — giving the blank line after ). (3) The four-space indent inside the brackets is part of the required answer.

What if $i++ were deleted?

$i would stay 1 for ever, $i > 5 would never become true, the break would never run, and the program would loop for ever — an infinite loop. In a while (true) the exit is entirely your responsibility.

PROGRAM 5

isset, empty and truthiness

6 MARKS

The favourite trick question of the whole syllabus. Learn the five rows below and it is free marks.

The code

$a = 0;        $b = "0";     $c = "";
$d = null;     $e = -5;
$vars = array("a"=>$a, "b"=>$b, "c"=>$c, "d"=>$d, "e"=>$e);
foreach ($vars as $key => $value) {
    echo $key . " -> ";
    if (isset($value)) { echo "isset:YES "; } else { echo "isset:NO "; }
    if (empty($value)) { echo "empty:YES "; } else { echo "empty:NO "; }
    if ($value)        { echo "truthy:YES"; } else { echo "truthy:NO"; }
    echo "<br>";
}

One pass per variable, three questions each

$a = 0
isset(0)  ->  YES   it exists, and is not null
empty(0)  ->  YES   0 counts as empty
if (0)    ->  NO    0 is the only false number
prints a -> isset:YES empty:YES truthy:NO
$b = "0"
isset("0")  ->  YES
empty("0")  ->  YES   !! the STRING "0" is also empty
if ("0")    ->  NO
prints b -> isset:YES empty:YES truthy:NO A one-character string, and still empty.
$c = ""
isset("")  ->  YES   an empty string still exists
empty("")  ->  YES
if ("")    ->  NO
prints c -> isset:YES empty:YES truthy:NO
$d = null
isset(null)  ->  NO   null is the ONLY thing that fails isset
empty(null)  ->  YES
if (null)    ->  NO
prints d -> isset:NO empty:YES truthy:NO The only isset:NO in the table.
$e = -5
isset(-5)  ->  YES
empty(-5)  ->  NO    -5 is not zero, so not empty
if (-5)    ->  YES   any non-zero number is true
prints e -> isset:YES empty:NO truthy:YES The only row that is truthy.

What the browser shows

a -> isset:YES empty:YES truthy:NO b -> isset:YES empty:YES truthy:NO c -> isset:YES empty:YES truthy:NO d -> isset:NO empty:YES truthy:NO e -> isset:YES empty:NO truthy:YES

Notice the shape: four rows are almost identical, and the two that break the pattern are d and e.

The two traps. "0" is a string with a character in it, and it is still empty — PHP treats it as the number zero. And -5 is true, because truthiness asks is it zero or not, never whether it is positive.

One-sentence definitions to memorise

isset() — does this variable exist and hold something other than null?
empty() — is this value one of 0, "0", "", null, false, or an empty array?

They are not opposites. Every value except null is isset, while five different values are empty. That overlap is exactly what the question is testing.

01

Session vs Cookie — explain the difference and say which one a login must use.

Answer in one lineA session is stored on the server; a cookie is stored in the browser. Login must be a session, because the user can edit a cookie.

Session — session_start() opens it, values live in $_SESSION on the server, and the browser only receives a session id. In the lab, $_SESSION['username'] = $username; in login-handler.php is the whole login, and every protected page then asks isset($_SESSION['username']).

Cookie — setcookie() writes it into the browser and it returns on every later request in $_COOKIE. The theme switcher is the lab example: setcookie('theme','dark', time()+60*60*24*7).

The answer they want: a cookie lives on the user's own machine, so they can open it and change it. Nobody may edit their way into being logged in — so login state belongs in a session. A theme is harmless and should survive until tomorrow, so a cookie is right for it.

Logging out uses session_unset() then session_destroy(). Deleting a cookie means setting it again with an expiry in the past: setcookie('theme','',time()-3600).

02

GET vs POST — differences, and which one the labs use where.

Answer in one lineGET puts data in the URL and is for reading; POST puts it in the request body and is for changing things.

GET — values sit after the ? in the address, so they are visible, bookmarkable and kept in history. Limited to roughly 2000 characters. The MVC router uses it for navigation: index.php?target=profile, read with $_GET['target'].

POST — values travel in the body, hidden from the address bar, no practical size limit, and it is the only method that can carry a file upload. Every form in the labs that changes something — login, register, insert, upload — is a POST.

This is exactly why every controller opens with

if ($_SERVER['REQUEST_METHOD'] == 'POST') { ... }

— so that somebody merely typing the handler's address (a GET) cannot trigger an insert.

03

What is MVC? State exactly what belongs in each layer.

Answer in one lineModel = all the SQL, View = the HTML, Controller = validate then redirect. index.php is the router.

Model (model/User.php) — every SQL statement in the application. It returns plain arrays and prints no HTML.

View (view/home.php) — the HTML. It may loop over data and echo it, but it must never contain a query.

Controller (controller/login-handler.php) — reads $_POST, validates, calls the model, then redirects. It prints nothing:

header("Location: ../");
exit();

Router — index.php calls session_start() once, then picks the view from the session and $_GET['target']. Everything enters through this one file.

Why bother: the login query is needed by several pages; in MVC it is written once. If the database changes you edit one file instead of twenty, and the layout and the logic can be worked on separately.

A separate DBConnection class holds the host, user, password and database name, so those four values appear in exactly one place.

04

Why must validation be done on the client AND the server?

Answer in one lineThe JavaScript check is a convenience and can be switched off; the PHP check is the only one that cannot be bypassed.

Client side — a JavaScript validateForm() wired up as onsubmit="return validateForm()". Returning false stops the form submitting. It is instant and needs no page reload. (Leave out the word return and the browser ignores your answer entirely.)

Server side — the same rules again in the controller, collected into an $errors array, handed back through the session and printed beside each field.

The answer they want: JavaScript runs on the user's own machine. They can disable it, or send the POST straight from a tool without ever loading your form — then validateForm() never runs. So the server check is the real one.

Some rules can only be checked on the server: “is this username already taken?” needs a database query, and the browser has no way to know.

Useful PHP helpers: empty(), strlen(), filter_var($e, FILTER_VALIDATE_EMAIL), preg_match(), is_numeric().

05

What is a superglobal? Name them and say what each holds.

Answer in one lineA built-in array PHP fills in automatically, reachable in every file and inside every function without declaring global.

$_GET — values from the URL after the ?.
$_POST — values from a form with method="post".
$_REQUEST — $_GET and $_POST together.
$_SESSION — server-side data; needs session_start() first.
$_COOKIE — cookies the browser sent back.
$_FILES — uploaded files; empty unless the form has enctype="multipart/form-data".
$_SERVER — information about the request and server.
$GLOBALS — every global variable.

The one used constantly is $_SERVER['REQUEST_METHOD'], which every controller checks. Others worth naming: PHP_SELF, SCRIPT_NAME, HTTP_HOST, QUERY_STRING, HTTP_USER_AGENT.

Watch out: an unticked checkbox and an unchosen radio group send nothing at all, so they must be read with isset($_POST['terms']) and never directly. Checkboxes named interests[] arrive as an array.

06

What is SQL injection, and how does a prepared statement stop it?

Answer in one lineInjection is when typed input becomes part of the SQL. A prepared statement sends the query first and the values separately, so input can only ever be data.

A query built by joining strings:

$sql = "SELECT * FROM users WHERE username = '" . $username . "'";

If somebody types ' OR '1'='1 the query becomes

SELECT * FROM users WHERE username = '' OR '1'='1'

— always true, so every row matches and they are logged in with no password.

A prepared statement sends the query text to MySQL first, with ? where the values will go. The values follow afterwards. MySQL has already decided what the query looks like, so a value cannot change its shape.

$sql  = "INSERT INTO users (username, email, password)
         VALUES (?, ?, ?)";
$stmt = $conn->prepare($sql);
$stmt->bind_param('sss', $username, $email, $password);
$stmt->execute();
$new_id = $conn->insert_id;

The type string carries one letter per question mark, in order: s string, i integer, d decimal, b blob. Three placeholders → 'sss'. A wrong count gives Number of variables doesn't match parameters.

07

What is AJAX? Explain synchronous vs asynchronous and the four steps.

Answer in one lineAJAX lets the page fetch data in the background and update part of itself without reloading.

Synchronous — the form submits, the browser waits, the whole page is replaced, and the user can do nothing meanwhile.

Asynchronous — the request goes in the background; the user keeps using the page, and when the reply arrives JavaScript redraws only the part that changed.

var xhr = new XMLHttpRequest();                    (( 1. create ))
xhr.open("GET", "api/get-users.php", true);          (( 2. open, true = async ))
xhr.onreadystatechange = function () {              (( 3. on reply ))
    if (xhr.readyState == 4 && xhr.status == 200) {
        var data = JSON.parse(xhr.responseText);
    }
};
xhr.send();                                         (( 4. send ))

readyState == 4 means the reply has fully arrived; status == 200 means the server reported success. Both must be checked — a 404 page also arrives completely.

The third argument of open() is true for asynchronous; false freezes the page until the server answers.

For a hand-written POST you must also send

xhr.setRequestHeader("Content-type",
    "application/x-www-form-urlencoded");
xhr.send("username=" + username);

or $_POST arrives empty. Forgetting xhr.send() means nothing happens at all.

08

Name the four JSON conversion functions and say when each is used.

Answer in one linePHP: json_encode / json_decode. JavaScript: JSON.stringify / JSON.parse.

Learn them as two pairs and they cannot be mixed up:

PHP
  json_encode($array)       array  -> JSON text
  json_decode($text, true)  JSON   -> associative array

JavaScript
  JSON.stringify(obj)       object -> JSON text
  JSON.parse(text)          JSON   -> object

Where each appears in the lab. The API endpoint builds an array from the model and prints it:

header('Content-Type: application/json');
echo json_encode($usersList);

and the page turns that text back into an array:

var data = JSON.parse(xhr.responseText);

The true in json_decode($text, true) asks for an associative array instead of an object.

When PHP is the one receiving a JSON body, read the raw input:

$post_data = file_get_contents("php://input");
$data = json_decode($post_data, true);

An API is not a controller. A controller redirects and prints nothing; an API prints data and never redirects. Put a header("Location: ...") in an endpoint and the JavaScript receives HTML, so JSON.parse throws.

09

Explain the two ways to store an uploaded file, and what enctype does.

Answer in one lineEither move the file into a folder and store its path, or read its bytes and store them in the database. Without enctype, $_FILES is empty.

Method 1 — save to a folder. The path goes in a VARCHAR column.

$tmp  = $_FILES['profile_pic']['tmp_name'];
$ext  = pathinfo($_FILES['profile_pic']['name'], PATHINFO_EXTENSION);
$name = time() . '_' . $_SESSION['username'] . '.' . $ext;
move_uploaded_file($tmp, '../images/' . $name);

Method 2 — store in the database. The bytes go in a LONGBLOB, together with the MIME type.

$bin  = file_get_contents($_FILES['profile_pic']['tmp_name']);
$type = $_FILES['profile_pic']['type'];
(( UPDATE users SET profile_pic = ?, profile_pic_type = ? ... ))

Because it is not a file on disk it has no URL, so it is printed as a base64 data URI:

echo '<img src="data:' . $type . ';base64,'
   . base64_encode($bin) . '">';

Three things that must be said:

1. enctype="multipart/form-data" on the form. Without it the browser sends only the file's name as ordinary text and $_FILES is empty — with no error shown anywhere.
2. Check the type against a whitelist: in_array($_FILES['f']['type'], ['image/jpeg','image/png']).
3. Rename with time() so two uploads of photo.jpg cannot overwrite one another.

An uploaded file sits in a temporary folder and PHP deletes it when the script ends — move_uploaded_file() is what rescues it.

10

File handling: the three fopen modes, and reading and writing XML.

Answer in one line'r' reads, 'w' erases then writes, 'a' appends. Always fclose() what you fopen().
'r'  read only, from the beginning; fails if the file is missing
'w'  ERASES the file first, then writes; creates it if missing
'a'  APPEND - keeps what is there and adds at the end

The pattern is always three steps — open, use, close:

$f = fopen("content.txt", 'a') or die("Unable to open file");
fwrite($f, "\nEEE");
fclose($f);

Reading the whole file needs the length, which is what filesize() gives:

$f = fopen("content.txt", 'r');
echo fread($f, filesize("content.txt"));
fclose($f);

(( or in one line ))
echo readfile("content.txt");

The classic mistake: opening a log with 'w' instead of 'a'. It looks like it works, but every write wipes the file and leaves a single line.

XML — reading gives you an object you can walk:

$content = simplexml_load_file("data.xml")
           or die("Unable to open XML file");
echo $content->to;
echo $content->body->main;   (( nested elements ))

XML — writing builds from a root element and saves the text:

$list  = new SimpleXMLElement('<?xml version="1.0"?><booklist/>');
$book  = $list->addChild('book');
$book->addChild('author', 'J.K Rowling');
$book->addChild('title', 'Harry Potter');
file_put_contents('booklist.xml', $list->asXML());

asXML() turns the object into XML text; simplexml_load_file() does the reverse.
